## 修复推送环（confirm 实弹两缺陷）

1. **stale 守卫误杀 confirm**：`pushVerifiedFixes` 的僵尸写守卫要求
   `task.Status=running`，但 confirm 放行时任务早已 `done`（评审环结束）——
   **每次 confirm 必落 `skipped_stale`**（43 jianmu#63 实弹复现）。修复=
   `await_confirm` 前提豁免（confirm 侧 head 绑定 + 远端 TOCTOU + 副作用闸
   仍兜底）；direct/branch 异步尾部推送的 running 守卫不变。
2. **confirm 形态错走 direct 直推**：`mode=confirm` 此前按 direct 直推 PR
   源分支且不开 CR，违反验收 T4「正确 head → 推送成功（branch 形态开修复
   PR）」。修复=`branchFormMode` 单源：confirm 与 branch 同形（修复分支
   `argus/fix/<n>` CAS 计划 + `openFixPR`）。

回归：`TestPushVerifiedFixesConfirmWhenTaskDone`（done+await_confirm 放行、
只推修复分支、PR 源分支零触碰）+ `TestPushVerifiedFixesStaleGuardStillBlocksDoneTask`
（direct 模式 done 任务仍 `skipped_stale`，守卫不回退）。
