# v8.8.6

> v8.8.5 在役实弹连抓两缺陷的修复（推送 refspec + 对账裁决器 confirm 键）。
> 零 DDL。43 换芯部署版本。

## 修复（均来自 43 真实 confirm 执行）

1. **detached HEAD 下短目标名 push 被拒**：工作副本按 PR SHA detached
   checkout，git 对 src 非 ref 的推送要求全限定目标——`HEAD:argus/fix/<n>`
   被 GitLab 拒（`destination ... not a full refname`）→ `push_failed` →
   副作用闸 `uncertain` → `push_skipped`。三处推送（branch 计划首轮/CAS、
   direct 直推）统一改 `HEAD:refs/heads/<target>`；CAS 夹具与 confirm 回归
   测试改 detached HEAD 同形（原 attached 夹具拦不住此缺陷）。
2. **confirm 键永不被对账裁决**：`PushResolver.parsePushKey` 只认
   `branch|direct`，`fix:push:*:confirm` 每分钟被 `unknown key type` 空转跳过。
   confirm 与 branch 同形（`branchFormMode` 单源）：入 parse 词表 + 分支
   存在性判据共用；补 confirm 已生效/未生效两态裁决测试。
