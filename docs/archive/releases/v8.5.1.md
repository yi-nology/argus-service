# v8.5.1

> 质量运营闭环 v2：让回复控制的生效结果**可见、可解释、可回归、可告警**。

## 本版内容

### 1. 回复控制结果透明化（修复 v8.4.0 承诺缺口）

- **报告尾注静默计数**：`severity_floor` / `findings_cap` 过滤掉的条数在
  standard / analyst / minimal 三套模板如实展示（"🔇 按仓库设置静默 N 条…"）。
  v8.4.0 发布说明写的「以下静默留计数」在默认模板此前未兑现，本版补齐；
  计数不受 `ARGUS_REPORT_META` 开关影响。
- **任务落库 + 聚合**：`tasks` 新增 `reply_state`（posted/throttled）、
  `silenced_floor`、`silenced_cap`（窄写口、best-effort，不回滚审查结果）；
  `GET /stats/overview` 按仓与全局返回三项计数。
- **GetTask 透出**：`GET /tasks/:id` 新增 `replyState` / `silencedFloor` /
  `silencedCap`（optional，零值不产出）——控制台可回答「为什么这轮没回帖」。
- **前端**：仓库设置「近 30 天生效情况」、总览页回复控制 30 天全局卡、
  任务详情展示回帖结果与静默条数；报告升级 Markdown 渲染（表格/代码块/链接）。

### 2. 意见治理台（跨 PR 指纹账本）

- 新增 `GET /findings`（IDL 收编，read 档 + 仓库维度判定）：按仓跨 PR 列出
  `finding_prints`，支持 `status=open|suppressed`、`limit`（缺省 100/上限 500），
  返回 total/open/suppressed 三计数。
- 前端新增「意见治理」页：浏览、状态/级别/关键词筛选、抑制/恢复
  （admin 档写操作；read 档显示只读）、超页提示；任务详情可直达该仓意见治理。
- 前端平台词表单源化（`src/constants/platforms.ts`）——修复仓库设置页此前
  使用 bitbucket/azure-devops/tencentcode 错误词表的漂移。

### 3. 质量门禁与可观测

- `make quality-gate`：最新两批同口径环比，F1 跌 >0.05 / 干净样例误报率涨
  >0.05 / Unlabeled 增 >10 即失败；跨口径切换线自动跳过（禁直比纪律可执行）。
- Prometheus：`argus_reply_throttled_total{platform,repo,tenant}`、
  `argus_findings_silenced_total{platform,repo,reason,tenant}`（reason=floor|cap）。
- 告警规则：节流率 / 静默率 >50%（30m）提醒检查仓级配置；顺修两条既有告警
  的 status 词表错位（`success/failure` → `done/failed`，此前规则永不触发）。

### 4. 租户隔离修复（P1 正确性）

- `PrintRepoSummary` 的 GORM `Scan` 绕过 Query 回调，租户谓词未注入，
  导致跨租户计数合并 → 改 `Model+Find`；同坐标隔离测试扩展
  （prints 列表/计数/回复频次时间查询）。
- **教训入库**：聚合查询必须 `Model(&X{}).Find`，`Scan` 不触发租户回调。

## 升级注意

- **DDL**：`tasks` 表新增三列（`reply_state` VARCHAR(16) DEFAULT ''、
  `silenced_floor`/`silenced_cap` INT DEFAULT 0），AutoMigrate / migration job
  自动补齐；纯增量、无回填、无破坏。
- **新接口**：`GET /findings` 为新增读面（Bearer + 仓库约束）；旧客户端无影响。
- **指标/告警**：新增两个 Prometheus 指标；`deploy/monitoring/prometheus-rules.yaml`
  增加两条告警并修复两条历史规则（建议同步更新）。
- **部署建议**：本版修复了 v8.4.0「静默留计数」的承诺缺口，建议直接部署
  v8.5.1，跳过 v8.4.0。
- 兼容性：无 breaking API/配置变更；`ARGUS_*`、repo_settings 旧值语义不变。
