## 控制面权限边界（P0 #60）

- admin 两级语义：无约束 admin = system_admin（全局）；`admin@pattern` =
  repo_admin（仅约束内仓库可见/可操作，与 repo-settings 既有口径自洽）。
- `admin@repo-A` 取消 repo-B 任务返回 403，任务状态与 `cancel_requested_at`
  不动；副作用裁决/租约强释从**库记录**解析资源身份（`pr:`/`branch:` 形态，
  `effect.ParseResourceRepo` 单源），列表接口按约束行过滤；不可归属资源仅
  system_admin 可见。拒绝路径留 token 指纹审计。
- 测试四层：e2e HTTP 路由矩阵（`TestAuthzControlPlaneRepoAdminMatrix`）+
  service 直调矩阵 + storage 读面 + effect 解析器/编码器回环。

## 自动修复的 Git 更新语义（#61/#62/#66）

- **#66**：Git 写凭证改经 `GIT_CONFIG_COUNT/KEY_0/VALUE_0` 环境注入，不再进
  子进程 argv（`ps` 可见面清零）；推送失败分类改显式 `gitStep` 标签，
  `argus_fix_push_total{step=}` 恢复 `commit_failed`/`push_failed` 可区分。
- **#61**：组合补丁最终验证——逐条通过 ≠ 组合可构建。Apply 后对组合树整体跑
  一次验证命令 + `git diff --name-only` ⊆ 预期写入集校验，任一失败落
  `push_failed`（`combined_verify_failed`/`diff_out_of_scope`）+ 清场，零远程
  提交；提交信息/PR 描述措辞只在组合通过后声明「组合构建验证」。
- **#62**：修复分支连续更新——push 前 `ls-remote` 读远端态；tip 归属校验
  （argus-bot 提交才允许重写）后以 `--force-with-lease=<ref>:<expected>` CAS
  更新；人工提交在 tip 拒绝覆盖（`branch_head_not_argus`）；并发只许一个赢家。
  禁止无条件 `--force`（roadmap「明确不做」）。

## 取消与外部写入围栏（#63）

- 取消复查放 effect **Prepare 阶段**（kernel Abandon 语义：未施加任何副作用
  即放弃，不落「结果未知」）：push 闸 `prepareFixPush`、CR 闸 `fixCRCancelled`；
  execute 链回帖前补检查点（原检查点④与回帖之间隔着分钟级窗口）。
- 取消后旧执行者不再获得平台写入许可：push 落 `skipped_stale`、PR 创建落
  `pr_skipped`。epoch/Intent 绑定留 v7.5（诚实边界不变）。

## 版本一致性（#65）

- `scripts/sync-version.sh <vX.Y.Z>` 一处版本源派生全部交付物（Chart
  appVersion/chart version/README/CHANGELOG/docs/releases）；`scripts/
  check-version-consistency.sh` 进 CI（`make version-check`），任一漂移红灯；
  tag 构建加 git tag 对账；Helm 模板镜像 tag 禁硬编码（同源 `.Chart.AppVersion`）。

## 升级注意

- 修复推送链新失败分类与状态（`combined_verify_failed`/`diff_out_of_scope`/
  `branch_head_not_argus` 等）都落既有 `push_failed`/`push_skipped` 词表，监控
  面无需新映射。
- `ARGUS_API_TOKENS` 中 `admin@pattern` 的 token 现在是 repo_admin：此前依赖
  它做跨仓控制面操作（取消/裁决/强释）的部署需换无约束 admin token。
