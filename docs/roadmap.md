## 0. 结论先行

Argus 下一阶段的主线不是继续横向增加功能，而是让现有能力在**多副本、并发修改、失败重试、权限受限**的环境下仍然表现正确。

优先级从高到低：

1. **控制面权限边界**（跨仓库越权，见 #60）；
2. **自动修复的 Git 更新语义**（组合验证 #61、非快进更新 #62）；
3. **取消与外部写入的围栏**（#63、#64）；
4. **双副本实时事件一致性**（#67）；
5. **成本硬约束与真实质量验证**（#68、#69 及评测基线）。

外部评审将当前工程成熟度评为 **8.5/10**（上一轮 8.2）。该分数是评审输入，不是本仓自评；扣分集中在控制面权限、自动修复的 Git 更新语义、跨 Pod 实时事件一致性。本文件不把评分当作验收指标，只采用其问题清单与方向判断。

## 3. 目标架构：模块化单体，不拆微服务

当前继续维持**模块化单体 + 共享 PostgreSQL + 多个 Worker 副本**。理由：

- 领域边界仍在快速变化，拆分会把领域复杂度转成分布式复杂度；
- 现有可靠性问题（权限、围栏、事件一致性）不是拆分能解决的，拆分只会放大；
- 代码规模已进入需要治理复杂度的阶段，应减少重复机制，而不是增加横向抽象。

目标结构：

```text
        ┌──────────────────────────────────────────────┐
        │ API / Webhook / MCP / Console                │
        │ Hertz + IDL + AuthN/AuthZ                    │
        └──────────────────┬───────────────────────────┘
                           │
        ┌──────────────────▼───────────────────────────┐
        │ Review Domain                                │
        │ Evidence / Verdict / Quality                 │
        └──────────────────┬───────────────────────────┘
                           │
        ┌──────────────────▼───────────────────────────┐
        │ Execution Domain                             │
        │ Task / Budget / Fix / Fencing                │
        └──────────────────┬───────────────────────────┘
                           │
        ┌──────────────────▼───────────────────────────┐
        │ PostgreSQL                                   │
        │ 状态 / Outbox / 账本                         │
        └──────────────────┬───────────────────────────┘
                           │
        ┌──────────────────▼───────────────────────────┐
        │ Event Transport                              │
        │ 可靠事件（Outbox） / 流式事件（临时通道）    │
        └──────────────────────────────────────────────┘
```

边界规则：

- **机制下沉、决策上浮**：goagent-kernel、OAgentKit、Git SDK 提供执行机制；Argus 保留领域决策权。
- **单一事实源**：任务状态、修复状态、副作用状态、预算预留状态各自只有一个写入者，跨状态机转换必须走显式 API。
- **事件分层**：可靠状态事件走 PostgreSQL Outbox；高频流式增量走低延迟临时通道，不把两者混在一条链路上。
- **权限分层**：仓库管理员（`repo_admin`）与系统管理员（`system_admin`）分离，不再让 `admin` 一词兼两义。

## 6. 工程治理两条规则

### 6.1 状态机单一事实源

下一轮代码审计逐项钉住「唯一写入者」与「允许的跨状态机转换」。当前状态词表（以代码为准）：

| 状态机 | 词表 | 目标唯一写入者 |
|---|---|---|
| 任务 | `pending` / `running` / `done` / `failed` / `stale` | runner 终态写入 + 控制面条件取消 |
| 修复状态 | `pushing` / `pushed` / `push_failed` / `push_skipped` / `skipped_stale` / `pr_created` / `cr_existed` / `pr_failed` / `pr_skipped` | runner `setFixStatus` |
| 副作用动作 | `pending` / `done` / `uncertain` | `internal/effect` + `internal/storage/side_effects*` |
| 预算预留 | `reserved` / `settled` / `released` | `internal/storage/budget_reserve.go` |

规则：

- 禁止跨包直接写状态列；所有转换必须经过带审计的 API。
- 每个状态机标注「允许谁转换」「失败时落到哪里」「谁负责对账」。
- 新增状态必须先更新本表，再写代码。

### 6.2 拆分按职责，不按行数

近期重构把部分方法拆成很短的转发壳，真正实现移入 `*_impl_*.go`。这降低了单文件体积，但不一定降低认知复杂度。后续拆分以**业务职责与变化原因**为准：

- 同一变化原因放一起，不同变化原因分开；
- 转发壳只在需要稳定门面/跨包契约时保留；
- 拆分后必须能用一句话说清两个模块的职责差异，否则不拆。

## 7. 明确不做

- **不拆微服务**：当前问题是正确性与治理，不是部署粒度。
- **不做无条件 `--force`**：修复分支更新必须 CAS（`--force-with-lease` + 期望旧 SHA）。
- **不在组合验证通过前推送**：单条修复验证通过不等于组合可构建。
- **不让 `admin` 一词继续兼两义**：仓库管理员与系统管理员必须可区分。
- **不引入第二套事件通道而不做取舍**：可靠事件与流式事件分层，但每类只保留一条主链路。
- **不以行数作为拆分唯一目标**：长函数治理以职责与可测性为准。

## 8. 度量与门禁

发布前至少保留以下门禁：

- `make test` / `make arch` / `helm lint` / 版本一致性检查；
- 三方言数据库矩阵（SQLite / PostgreSQL / MySQL）；
- 混沌场景：进程死亡、租约过期、取消竞态、复制延迟；
- 质量指标：P / R / F1、干净样例误报率、Unlabeled 占比、Evidence 各状态分布；
- 成本指标：每任务 token、soft/hard 预算触发次数、网关限流/降级次数；
- 延迟指标：审查尾段 p95、SSE 首事件延迟、跨 Pod 事件延迟上界。
